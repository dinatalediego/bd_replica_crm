# Medallio Forecast Factory Contract v1

## Purpose

This contract makes the forecasting layer model-agnostic.

Power BI should not care whether a forecast came from:

```text
Naive
Seasonal Naive
ETS
ARIMA / SARIMA
Elastic Net
Random Forest
XGBoost
LightGBM
Hierarchical Forecast
Bayesian model
Neural model
Ensemble
```

Every model must finish by writing the same canonical interface.

---

# 1. The seven canonical objects

## A. Model Registry

```text
model_control.forecast_model_registry_v1
```

One row per model version.

Answers:

```text
What is this model?
Which version?
Who owns it?
What family?
What code/artifact generated it?
Is it challenger or champion?
```

---

## B. Forecast Run

```text
model_control.forecast_run_v1
```

One row per issuance run.

It freezes:

```text
issued_at
data_cutoff_date
training window
feature_version
dataset_snapshot_id
code_sha
parameters
```

This is the issuance proof.

---

## C. Prediction

```text
analytics.forecast_prediction_v1
```

Canonical grain:

```text
run
× project
× target
× segment
× forecast period
× horizon
```

Every prediction MUST contain:

```text
prediction
prediction_lower
prediction_upper

naive_method
naive_prediction

model/run identity
horizon
evidence class
data cutoff
```

No naive benchmark = contract failure.

No interval = contract failure.

---

## D. Actual

```text
analytics.forecast_actual_v1
```

This is not generated by the model.

It is the canonical outcome ledger.

A forecast cannot mature until:

```text
period_complete = true
```

This protects the system from evaluating an incomplete October against a full-month forecast.

---

## E. Evaluation

Canonical mature-pair surface:

```text
analytics.v_forecast_mature_pairs_v1
```

It produces:

```text
signed_error
absolute_error
APE

naive_signed_error
naive_absolute_error
naive_APE

interval_hit
interval_width

leakage_safe
```

---

## F. Performance

```text
analytics.v_forecast_performance_v1
```

Metrics:

```text
WAPE
Bias
Naive WAPE
Skill vs Naive
Interval Coverage
Mature Pairs
Leakage Safe Pairs
```

Definitions:

```text
WAPE
= Σ|forecast-actual| / Σ|actual|

Bias
= Σ(forecast-actual) / Σ|actual|

Naive WAPE
= Σ|naive-actual| / Σ|actual|

Skill vs Naive
= 1 - WAPE / Naive WAPE
```

Interpretation:

```text
Skill > 0  → model beats naive
Skill = 0  → ties naive
Skill < 0  → naive was better
```

---

## G. Evidence

```text
model_control.forecast_evidence_v1
```

Evidence may include:

```text
ISSUANCE_PROOF
DATA_CUTOFF_PROOF
MODEL_CARD
FEATURE_MANIFEST
BACKTEST_REPORT
MATURE_OUTCOME
BUSINESS_USE
APPROVAL
```

Backtest evidence remains `BACKTEST`.
It is never silently promoted to `PROSPECTIVE`.

---

# 2. Defendability Gate

```text
analytics.v_forecast_defendability_v1
```

Default CEO policy:

```text
WAPE <= 25%
mature prospective pairs >= 6
Skill vs Naive >= 0
interval coverage >= 60%
leakage-safe evidence only
```

Those thresholds are policy, not hard-coded truth.

They live in:

```text
model_control.forecast_gate_policy_v1
```

and can be changed without redesigning the Power BI model.

Statuses:

```text
PASS
WARN
INCUBATING
BLOCK
```

---

# 3. Stable Power BI contract

Power BI should connect to:

```text
analytics.v_pbi_forecast_factory_current_v1
analytics.v_pbi_forecast_performance_v1
analytics.v_pbi_forecast_evidence_v1
```

Future models write the contract.

Power BI remains unchanged.

That is the architectural payoff.

# 4. Forecast lifecycle

```text
MODEL VERSION
      ↓
RUN ISSUED
      ↓
FORECAST ROWS
      ↓
INCUBATING
      ↓
ACTUAL PERIOD CLOSED
      ↓
MATURE
      ↓
EVALUATION
      ↓
WAPE / BIAS / SKILL / COVERAGE
      ↓
DEFENDABILITY GATE
      ↓
CHAMPION / CHALLENGER DECISION
```

---

# 5. Prospective evidence rule

To count as prospective evidence:

```text
data_cutoff_date < forecast_for_period
issued_at < period_closed_at
evidence_class = PROSPECTIVE
```

Backtests can train and diagnose models, but they do not prove prospective performance.

---

# 6. Segment support

The contract deliberately supports:

```text
project_key
segment_key
```

Examples:

```text
ALL

BEDROOMS=1
BEDROOMS=2
BEDROOMS=3

TYPOLOGY=T1
TYPOLOGY=T2

BEDROOMS=2|TYPOLOGY=T4
```

So a future hierarchical model can forecast:

```text
Portfolio
Project
Bedrooms
Typology
```

without changing the schema.

---

# 7. Targets

Recommended first targets:

```text
sales_units
absorption_rate
months_to_zero
```

Do not force different target units into one model.

A model version belongs to a target.

# 8. Installation

```powershell
powershell -ExecutionPolicy Bypass `
  -File .\scripts\83_install_forecast_factory_contract_v1.ps1
```

Then:

```powershell
python .\scripts\forecast_factory_contract_v1.py status
```

Initially, an empty but healthy factory is expected:

```text
no runs yet
no predictions yet
no mature evaluation yet
```

---

# 9. Adapter rule for future models

Every forecasting notebook/pipeline should finish with an adapter.

Template:

```text
adapters/forecast_model_adapter_template.py
```

The model may produce whatever internal objects it wants.

The adapter must convert them to the canonical prediction columns.

That is how model innovation becomes decoupled from reporting.

---

# 10. What comes next

The first production implementation should not start with ten models.

Recommended order:

```text
1. sales_units, project × month
2. Naive / Seasonal Naive baseline
3. one statistical challenger
4. one ML challenger
5. prospective issuance
6. maturity
7. compare
8. promote champion only after mature evidence
```

Then extend to:

```text
bedrooms
typologies
hierarchical reconciliation
pricing / elasticity scenarios
```
